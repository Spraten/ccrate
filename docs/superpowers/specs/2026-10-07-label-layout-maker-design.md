# Label layout maker design

Status: reviewed design accepted for implementation by the user’s explicit request on October 7, 2026. PrintDesignPro and the documented defaults are selected. Coordinated execution uses Luna Medium coding workers and Sol High review. Deployment remains separately gated by AGENTS.md.

## Intended result and chosen defaults

Managers design reusable item labels in native CACI-Create and Equipment Terminal, then select real Homebox items to preview and print. Reuse PrintDesignPro's existing editor, commands, geometry, variable resolution and rendering instead of rebuilding those features. Preserve its text, image, shape, alignment, snapping and undo facilities. Dynamic fields initially bind only the native item name, native `assetId` (the shorthand), and the unchanged `/item/{native UUID}` QR payload. Static decoration does not represent live condition; no status binding is inferred. Neither personal badges nor arbitrary QR generation belongs to this feature.

Support two output profile IDs, `supvan` and `letter`. SUPVAN uses the current 40 × 30 mm stock, 8 dots/mm, maximum 384-dot print width and 16-dot feed reserve: its editable/printable area is 40 × 28 mm, producing 320 × 224 dots. Standard paper initially uses US Letter, 215.9 × 279.4 mm, 60 × 40 mm cut-out labels, 10 mm page margins and 3 mm gaps: 3 columns × 6 rows, 18 labels per sheet. Paper label size, margins and gaps are adjustable; validate fit rather than silently scaling. Size changes resize the document canvas, retain element positions for explicit adjustment, and require Save and a new review. Each review binds its profile, `label_mm` and `dpi`; every paper slot must exactly match reviewed physical dimensions at 300 DPI, without scaling/cropping or mixing SUPVAN and paper output. Sheet geometry input is `{page_mm:[215.9,279.4],label_mm:[w,h],margin_mm:number,gap_mm:number,cut_guides:boolean}`; validated output adds `columns` and `rows`. Cut guides occupy gutters and never QR quiet zones. These are reversible defaults, not assumptions about a particular adhesive stock.

Ship three starter designs per profile using the same library: QR left/name right, QR above/name below, and a compact name/code arrangement. Their six immutable IDs follow `starter:{profile}:{left|top|compact}`. Every starter has a readable item QR and native text fields; keep several starters usable without editing. Long names wrap inside their box and use an explicit truncation indication when they cannot fit. Empty asset codes render blank. The reversible nominal font-size floors are 2.25 mm for SUPVAN and 3 mm for paper, converted exactly into the pinned library's font units; never shrink below those floors merely to hide overflow. These are nominal font sizes, not glyph ink heights or proven human legibility. Preview warns about truncated/empty fields, and numeric editing accompanies pointer controls.

## Why PrintDesignPro

PrintDesignPro is an MIT Vue 3 editor package whose Vue `^3.5` and Pinia `^3` peers match the installed native stack. Its source package reports `0.1.0` and is not yet npm-published. It provides more of the desired editor than QRLayoutTool, whose framework-independent embedding is simpler but whose documented element types are text, QR and barcode. The selected route is to adopt and constrain PrintDesignPro; retain QRLayoutTool only as a fallback if isolated acceptance exposes an objective blocking defect. Do not reopen selection for routine integration choices.

Acquire a complete upstream revision during the first execution task, record its full commit SHA and license, and build the editor as an independent ESM asset bundle. The public web source did not yield a reliably verifiable full SHA during planning; no floating revision is an acceptable release pin. Do not upgrade Homebox's Nuxt, Vue, Pinia, Tailwind or pnpm toolchain to match the upstream demo application. Preserve MIT notices and the license for any locally bundled fonts. UMD is unsuitable because upstream documents excluded QR/barcode/PDF features there.

References: [project/embedding](https://github.com/arenahub-gg/print-design-pro), [package](https://github.com/arenahub-gg/print-design-pro/blob/main/packages/editor/package.json), [renderer](https://github.com/arenahub-gg/print-design-pro/blob/main/packages/editor/src/render/render-engine.ts), [QR painter](https://github.com/arenahub-gg/print-design-pro/blob/main/packages/editor/src/render/element-painters/paint-qr.ts), [font loader](https://github.com/arenahub-gg/print-design-pro/blob/main/packages/editor/src/core/fonts.ts).

## One editor and one authoritative renderer

Build one standalone Vue/Pinia editor host around the existing `PrintDesigner` component and documented `createEmptyTemplate` helper. Both interfaces embed this identical locally served host through a small iframe adapter, isolating its styles and runtime from native Tailwind 3 and the vanilla Terminal. The pinned same-origin editor JavaScript is trusted application code. The iframe isolates styles/runtime, not security: same-origin cookies, parent access and authenticated local HTTP are available as expected. The wrappers own normal account/group requests without explicitly passing tokens. Exact origin/source/instance-nonce checks prevent stale or misrouted enumerated messages; they do not sandbox the editor. Scoped CSP permits local application assets/fonts and validated data images, denies runtime external requests, and disables objects; no cross-origin capability subsystem is introduced. Leaving a dirty draft or a pending confirmation uses the existing unsaved/pending guards. Collection/account changes dispose the old host; late replies never repopulate it. No new inventory or user authority is introduced. Terminal iframe text/numeric fields request the existing parent `touchKeyboard(input, options)` through a validated field-ID/instance-epoch bridge; edits return only to the still-current field. Parent dirty/busy/dispose/session-activity wiring covers iframe interactions, Back/Cancel and identity transitions, including an 800 × 480 touch-only terminal and narrow mobile view.

Reuse `renderToCanvas(doc, {dpi, background})`, an exported function in the inspected source, and the existing sheet composition code (`core/sheet-layout.ts`, `render/export-sheet.ts`, `render/print-browser.ts`) after their exports/behavior are verified against the pin. A trusted render entry imports verified source paths if the public package entry does not export a needed helper. `label-ui/src/render-entry.ts` owns `composePaperSheet(reviews, geometry)` as a thin adapter to that engine and exposes it to the subprocess. Do not port the renderer to Pillow or create a second sheet engine.

The companion invokes installed Python Playwright/headless Chromium in a bounded subprocess to run the same bundled renderer. Render in a fresh context with no cookies, native credentials or local-file access. Fulfill only release-manifest assets through an intercepted synthetic origin; deny every other request, including font/image network requests. JSON arrives over stdin and PNG output over stdout; diagnostics never contain item data. Allow only local bundled fonts and validated embedded image data. Rendering time, input, canvas dimensions and output size are bounded. Begin with one subprocess per request; add a resident worker only if measured latency requires it. Label read/render routes acquire the existing shared lock with a two-second maximum wait and impose a 20-second whole-request render deadline, including batch/sheet work. Scoped preview/paper client deadlines are 60 seconds; existing durable writes retain their 25-second deadline and recovery semantics. Busy/timeout/size errors tell users to select fewer items or preview again, never imply physical output uncertainty for a read. Requests allow at most 36 reviewed items and two Letter pages, with explicit over-limit rejection.

Use 203.2 DPI for SUPVAN, exactly 8 dots/mm, and 300 DPI for paper. Flatten SUPVAN rendering onto white, convert to Pillow mode `L`, then threshold luminance at 128 without dithering: pixels below 128 become 0, the rest 255. Encode the authoritative canonical PNG without time-dependent metadata; decode its final QR successfully before freezing/storing it. `sha256` means the SHA-256 of those canonical PNG bytes; adapter input is their exact decoded `L` bytes, tested separately for equality. QR cells must already be integer-aligned, so normalization does not compensate for a malformed QR. Paper retains RGB rendering. Original Pillow `render` remains the legacy location/badge renderer. Their payloads, private badge handling and print recovery remain unchanged.

## Print-safe validation

The inspected upstream QR painter uses zero margin and silently ignores generation failure. Patch that reused painter and its validation narrowly: four-module white quiet zone, integer module rasterization, at least four dots/module for SUPVAN, square geometry, no skew/nonuniform scaling and visible failure when the data cannot fit. QR boxes include the protected quiet zone. Reject any other element crossing it, any crop or out-of-bounds QR, and a missing/extra item QR; the backend supplies its content from the item UUID. QR generation errors block preview/print. Decode final rasters to verify the original payload.

Replace the upstream Google Fonts loader with an allowlist of locally bundled fonts. Missing fonts fail before measurement; never silently use another font. Apply bounded schema validation to every template, not only the rendered PNG: reject unknown versions/elements, nonfinite or invalid geometry, unsafe styles/URLs, more than 128 elements, text/content longer than 1000 characters per element and embedded PNG/JPEG images larger than 512 KiB of compressed file bytes after base64 decoding. Each decoded image and individual output canvas/page is separately capped at 12 million pixels; untrusted document/preview input is capped at 1 MiB. Trusted reviewed-PNG sheet composition has a separate 32 MiB decoded JSON/stdin ceiling, at most 36 tickets/two pages; final aggregate encoded output is capped at 16 MiB. Image-heavy input may be clearly rejected within these bounds, never silently downgraded. Permit the fixed bundled CACI-Create SVG logo only through its manifest asset identity, never uploaded SVG/HTML or arbitrary URLs. Initial local font/logo and bounded image support need no asset service. Do not accept client-generated PNGs as authoritative print input. Expose the upstream label-capable elements; receipt/table workflows and CSV-driven inventory import are not new product workflows. Existing item import creates native records through its current reviewed process.

## Shared templates and reviewed outputs

Store documents in a new private companion `label-layouts.db`, using the existing SQLite group/revision pattern in `ops/workshop.py`. Templates contain geometry, static decoration, allowlisted local assets, a profile and field bindings; never a saved copy of selected item values. Backend-derived collection UUIDs own templates. Existing Workshop managers may list, create, duplicate and edit; existing label print permissions remain unchanged. Starter definitions are immutable. Duplicate saves a new identity, Save uses an optimistic revision, Reset restores the saved draft (or starter), and Cancel discards only unsaved changes. Concurrent saves return a conflict rather than overwrite another manager's edits. Save deduplication lives in the same SQLite transaction: `(group,actor,request_key)` plus canonical payload hash and committed result. Identical replay returns that original result/revision even if a later save exists; a changed payload conflicts. This is label-save idempotence, not a new operational/recovery journal or an assumed `once` integration.

A selected-item preview consumes `{mode:'item',entity_id,template_id,template_revision}` and creates an actor/group-scoped reviewed-output ticket containing the final PNG, raster hash, item UUID/`updatedAt`, template ID/revision/hash, profile, `label_mm` and `dpi`. The same endpoint may accept ordered `entity_ids` instead of `entity_id`, returning `{reviews:[itemPreviewResponse]}` under the shared 36-item/deadline limits; a failed batch issues no partial response for printing. Draft preview consumes `{mode:'synthetic',profile,document,sample:{item_name,asset_code}}`; its QR uses a fixed synthetic UUID and it returns no review ID. Nonprintable actual-item draft preview consumes `{mode:'item_draft',entity_id,profile,document}`; it fetches current native values, returns the base preview response without a ticket, and neither saves nor autosaves the draft. The response is `{image,width,height,sha256,profile,warnings}` plus `{review_id,item_updated_at,template_id,template_revision}` only for item mode. The ticket is temporary print intent, not inventory authority. Unattached tickets expire after 24 hours; tickets attached to an unresolved durable print are retained until Recovery resolves it. Completed/cancelled output purges PNG/value snapshots; retain only safe IDs, dimensions, hashes and outcomes needed by the journal. Draft preview does not save a template; physical printing uses an explicitly saved revision or immutable starter.

Before sending SUPVAN output, recheck native item version, template revision, permissions and probed stock against the ticket. Reject a changed item/template/stock and require a new preview; send exactly the reviewed raster bytes. A repeated completed request returns its saved outcome even after ticket purge. Same-key different intent conflicts; another key cannot print an item with unresolved output, regardless of native dialog, Terminal or import origin. An old unreviewed prepared item print is not upgraded into an automatic send. Attach the reviewed ticket before a new `NativeJobs.sent_print(group,job,entity_id,review_metadata)` transition. Within one ledger transaction it verifies a prepared `print_label`, validates the saved native UUID and allowlisted metadata-only reviewed event, records that event before the started event, and atomically writes `sent` plus `result_id`. Hardware output follows only after commit, removing the sent/bind gap. Cancellation through `recover_print` is permitted only for provably unsent prepared prints with no started marker; sent/uncertain prints require inspection-only acknowledgement. A legacy sent-before-bind item may be explicitly acknowledged/bound to the strict UUID in its saved payload without printing. Both actual recovery dispatchers inject layouts and purge attached temporary output only after resolution. No uncertain print is automatically retried.

Before paper export, recheck manager/group/actor permissions, ticket expiry and every native item/template version, then compose only same-profile, exactly matching reviewed dimensions into the selected geometry using the reused library. The renderer entry returns `png_base64`; the Python API returns JSON-ready `{pages:[{image:dataURI,width,height,sha256}],geometry}`. Browser print opens the user's printer dialog; show Actual Size/100%, correct paper and disabled headers/footers instructions. Do not treat `afterprint`, dialog closure or PDF download as physical completion. Paper output and SUPVAN import `label_status` are distinct: exporting paper cannot mark a Pi label printed. Cancelled paper dialogs leave the reviewed sheet viewable; each explicit new Print/PDF action rechecks the review IDs through the paper endpoint and exports only its authoritative returned page images/geometry. Client export never rerenders the editor draft or fetches replacement item values, and displayed/exported page hashes match the returned hashes.

## Integration boundaries

Extend `ops/labels.py:preview(client, entity_id)` and `print_label(client, jobs, group, actor, key, entity_id)` with explicit template/review arguments for item labels; keep their location/badge calls compatible. Add shared template/preview dispatch in `ops/desktop_api.py`, and map local Terminal routes in `deploy/kiosk-server.py` through the same label service under existing `OPEN_ADMIN` and lock. Native requests derive the selected collection from the authenticated context, Terminal from its current approved service-account group. Neither template IDs nor supplied group/actor fields grant access.

Integrate the native PiPrint dialog and `/workshop/labels` queue, Terminal `showLabel`, and both import label queues. Native queue selection is currently mount-local and navigating to `/items` loses it; provide a searchable ordinary-item picker directly in the label queue using the existing `api('equipment')` helper, and an equivalent Terminal picker. Keep selected UUID order in manager/account/collection-scoped memory, clear it on context changes, and never depend on a route handoff. Selecting 19 items, choosing profile/template, reviewing and composing two pages must work entirely within this workflow. Pass reviewed tickets through `Imports.label(client,jobs,group,data,*,actor=None,layouts=None)` using its existing durable row keys. Both dispatchers inject the current authorized confirming actor, not the batch uploader; that actor owns the preview ticket and print audit. Keyword defaults preserve old fixture/legacy calls, never bypass review on a new item print. Store pending review identities with existing per-row intent; refresh stale previews before explicit confirmation, never auto-repeat an interrupted print. Preserve already printed imports and all existing history. Do not modify upstream Homebox directly; use the overlay/builder.

## Acceptance and execution boundaries

Acceptance requires offline loading in both interfaces; drag/resize/alignment/undo/save/duplicate/reset with pointer and numeric/keyboard access; synthetic and selected-item previews; exact QR decode; template isolation and concurrent-save conflicts; cross-interface equal raster hashes; identical reviewed PNG versus mocked adapter bytes; changed-stock/item/template rejection before send; print deduplication/recovery; and correct paper pagination/physical CSS dimensions. Physical scanning, paper scale/legibility and disconnect acceptance remain separately authorized hardware gates. Browser/renderer parity cannot guarantee a user's printer settings or physical result.

Preserve the current approved-fix queue and `work/review-fixes-isolation`. These draft documents are the only changes authorized now. After written review, execute from a separate preserved isolated source snapshot after the approved fixes; rebase the plan's seams against that accepted source. Use the coordinating agent plus GPT-6.1 Sol High for requirements and risk review, one GPT-6 Luna Medium coding worker at a time with scoped context, and fixes/tests/renewed review before advancing.
