# Label editor build

Task 1 pins the MIT-licensed [PrintDesignPro](https://github.com/arenahub-gg/print-design-pro) editor at full commit `eb118cc05b169c554066d823c44dc179aa3b96bb`. Its `packages/editor/src` tree and upstream `LICENSE` are in `label-ui/vendor/print-design-pro/`. `label-ui/vendor-manifest.json` records the upstream source, offline-font patch, font source and notice. The build also records SHA-256 values for the vendored tree, patch, locked dependency graph, bundled font and each generated runtime asset.

The standalone editor mounts the upstream `PrintDesigner` Vue component with Pinia. The render page imports the actual `renderToCanvas` implementation and validates input using the pinned `templateDocumentSchema`; it does not implement a second canvas renderer. The checked upstream public exports include `PrintDesigner`, `createEmptyTemplate`, `renderToCanvas`, `computeSheetLayout`, `printDocumentBatchSheet`, and `exportPdfBatchSheet`. The render adapter uses the direct `render/render-engine` module because the task requires its Promise-returning canvas interface, not PNG/PDF export wrappers.

PrintDesignPro stores text size as `fontSizePt`. Its renderer converts to millimetres with `pt * 25.4 / 72`, so the inverse conversion is exactly `mm * 72 / 25.4`: 2.25 mm is `6.377952755905512 pt`, and 3 mm is `8.503937007874017 pt`. The adapter exports `mmToFontPoints` for those profile floors. The upstream font module loaded Google Fonts for several entries and silently fell back on failures. This package replaces that loader with an explicit local DejaVu Sans face and rejects unsupported document fonts; the TTF and its Debian copyright/license notice are local assets. No runtime font CDN is used.

The upstream schema is version 1: `{schemaVersion,id,name,page,elements,guides,variables}`. Page geometry and element positions/sizes are in millimetres; element geometry includes `xMm`, `yMm`, `widthMm`, `heightMm`, and `rotation`. `label-ui/src/starter-documents.json` is the shared canonical source for the six immutable profile/layout starters in the Python service and TypeScript renderer. All contain one item QR, item-name token and asset-code token. Saved documents are validated against the upstream schema and profile rules; sample values are stripped from saved templates. On render, the adapter runs upstream `resolveDocument` and `renderToCanvas`, binds `/item/{UUID}`, and rejects any QR that does not decode to the bound item path from the exact canonical PNG bytes.

`computeSheetLayout` accepts optional margin, gap and orientation settings while retaining its 5 mm / 2 mm / auto defaults for existing callers. Letter output uses 10 mm margins, 3 mm gutters and portrait orientation. `renderReviewedSheetBlobsFrom` reuses the upstream sequential sheet loop to place decoded frozen review PNGs without rerendering live values; optional cut guides are drawn in gutters. Sheet slots must match the reviewed label dimensions exactly, and output is limited to two Letter pages.

The private `LabelLayouts` SQLite service stores group/actor-scoped templates and frozen review records. Saves use optimistic revisions and request-key deduplication in one transaction; a replay returns the original saved result. Synthetic and item-draft previews issue no ticket. A batch item preview fetches and renders all items before atomically storing any tickets, each containing canonical PNG bytes, hash, profile geometry, template revision/hash, item identity/update time, and warnings. Task 3/4 add the group-scoped API, editor host and separately confirmed SUPVAN print workflow; Task 5 adds the reviewed Letter sheet actions described below. Unattached records expire after 24 hours.

`ops/label_render.py` launches a sanitized subprocess and one Chromium page for a render batch, serving only manifest-listed assets from an explicitly selected staged build root. Its 20-second whole-request budget includes manifest checks, raster canonicalization, QR decoding and result processing; the subprocess and Chromium process group are terminated on timeout. SUPVAN output is 320 × 224 L-mode PNG at 203.2 DPI, thresholded at 128 with no dithering. Letter labels default to 60 × 40 mm at 300 DPI and are RGB PNGs. Both profiles are re-decoded after canonicalization. All rendered QR modules use integer device-pixel cells and a four-module white quiet zone; SUPVAN requires at least four pixels per module.

Build with the existing Node 24.21.0 and pnpm 10.28.0 toolchains:

```sh
python3 deploy/build-label-ui.py --source-root . --output work/label-ui-build
PYTHONPATH=ops:kiosk:work/hardware/python python3 deploy/verify-label-layouts.py --compatibility-only --source-root . --output work/label-layout-verification --offline
```

The build script confines output under the isolated `work/` directory and only replaces an output directory it previously marked as its own. It installs from the package lock, never writes into the native frontend toolchain, and stages a `manifest.json` with runtime asset, source, lockfile, patch, font and license hashes. The Vite base and font URL are relative; the verifier serves the generated editor and renderer below `/workshop-api/label-assets/`, with no root asset fallback. Task 2 renderer tests exercise the real browser build for all six starters, canonical QR round trips, quiet-zone pixels, deterministic hashes, and a 19-label frozen Letter batch composed as two exact-size pages. Native API routes, login/authorization, host integration and print dispatch remain Task 3/4 work.

## Reviewed Letter print and PDF export

In either the native Label maker queue or Equipment Terminal, select saved Letter labels and choose **Review selected labels**. The queue preserves the chosen UUID order. Compose, Print and Download PDF each make a fresh `labels/paper` request (Terminal: `/label/paper`) for the same saved review IDs; the companion rechecks actor, group, ticket expiry, item version, template revision, profile and exact `label_mm` before returning any page bytes. The slot size is read from those reviewed tickets. Page margin and label gap remain editable; a geometry that cannot fit without scaling, or whose rounded slot pixels overlap, is rejected by the shared PrintDesignPro sheet layout. Cut guides are clipped to raster gutters and skipped when a gutter cannot contain the guide stroke, so they never alter frozen label pixels.

The browser displays and exports the page PNGs returned by that request. The PrintDesignPro frozen-page adapter prints those PNG bytes at US Letter size with one explicit page break per page. The PDF adapter embeds those same PNG bytes at 215.9 × 279.4 mm. Neither action rerenders the editor or refetches item values. When prompted to print, select **Actual Size / 100%** and disable browser headers and footers. Browser dialog close or `afterprint` events do not confirm physical output. The status text leaves the pages available and marks output unconfirmed; another Print/PDF action obtains a new authoritative response.

The renderer host is served with a scoped CSP that permits only its local assets and same-origin nested frame needed by PrintDesignPro's browser print helper. A missing renderer module, font or generated chunk causes an explicit export error. The offline verifier checks the generated bundle, the asset endpoint, same-origin print frame, and an ordinary HTTP LAN-like origin where `crypto.randomUUID` is unavailable. The label bridge and editor use UUIDv4 values from `crypto.getRandomValues` on that origin and still reject stale or forged messages. Focused native and Terminal queue fixtures exercise fresh paper authority and stale-review guards.

`deploy/backup-deployment.py` now has import-safe checkpoint, manifest and archive helpers that accept explicit roots. Its production `main()` remains the only path that stops services or reads private runtime data. Fixture archives include `work/ops/label-layouts.db`, the editor source, font and license, built runtime bundle and manifests. `deploy/runtime-manifest.py` and `deploy/install-shared-tools.py` likewise expose pure/fixture helpers while keeping their operational entry points behind `main()`.

A public candidate is assembled under `work/label-layout-release-candidate` by `deploy/stage-label-release.py`. Its `release-manifest.json` hashes every staged file and records the native binary/static UI, Terminal/Python sources, editor bundle, dependency lock, upstream commit, patch, font and license linkage. It contains no private runtime database. The previous public snapshot and bounded acceptance receipts are included as rollback provenance when their hashes match. Those receipts do not prove compatibility of the older print/recovery code with new reviewed-label intents: code rollback while such an intent remains unresolved must preserve the companion database and wait for the intent to be resolved. No release selector or deployment action is part of this change.

Paper output never changes Pi printer status or import status. SUPVAN still uses the existing separately confirmed physical Pi print workflow; physical scale, scanning and disconnect acceptance remain separate hardware checks.
